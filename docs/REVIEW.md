# Fixes and validation

## Provenance and scope

This repository started from the uploaded Computer Networks midterm archive. It contained six Python modules, four frontend files, example targets, installation files, two Markdown documents, a proposed directory sketch and ten compiled Python cache files.

The original README, HOWTO and structure image are archived unchanged. The application has received the correctness fixes below; this is a revised version of the course project. Generated Python caches are excluded. Contributor details and individual contribution splits were not supplied and are not inferred.

The archive contained no actual trace output, packet capture, final written report or measured performance evidence. The original structure sketch is a proposal rather than the actual layout: Python files live at the repository root, the frontend directory is `frontEnd`, and its stylesheet is `style.css`.

## Correctness fixes

| Area | Revised behavior |
| --- | --- |
| DNS option | `--no-dns` reaches every probe function and skips reverse lookups; destination hostnames still need forward DNS |
| TCP/ICMP classification | TCP requires SYN+ACK together or RST; reached responses must originate from the destination; unreachable responses are distinguished from timeouts |
| RTT timing | A monotonic performance counter measures elapsed time; valid zero RTT samples are retained |
| Repeated-query reporting | Text columns average all available samples separately for ICMP, UDP and TCP; JSON preserves every stored observation |
| Missing/error records | Probe exceptions become explicit ERROR records; empty/incomplete hops are exportable, with timeout and error counts reported separately |
| Graph transformation | Observations are grouped by TTL and protocol before links are constructed, so repeated samples do not create extra same-hop links |
| Graph uncertainty | Gaps and alternatives are flagged in edge data, dashed in the graph and explained in edge details; links remain inferred |
| Text rendering | Detail/summary text is escaped; loading-error text is inserted through DOM text properties |
| CLI validation | Validate TTL/port/payload ranges, query counts, finite timeouts/waits and TTL ordering |
| Interruption | Ctrl+C preserves collected observations, including the current partial hop, saves them and stops before later targets with exit code 130 |
| Environment | Pin tested Scapy 2.8.0 and use the same virtual-environment interpreter for install, probing and tests |

Probes remain sequential. The updated README describes this accurately; concurrency has not been added.

## Verification completed

The offline suite passed **20 Python tests and 6 Node tests**, using Python 3.12.14, Scapy 2.8.0 and Node v24.19.0.

- Scapy packet construction is real; packet send/receive, DNS and probe waiting are mocked.
- Test setup disables Scapy's native interface/socket initialization and routing-table autoload so offline tests do not need host packet privileges.
- Packet tests cover ICMP/UDP/TCP outcomes, timeouts, reverse-DNS toggling, TCP flag combinations, reply-source checks and quoted packets.
- Tracer tests cover repetition counts, stop conditions, local errors, interruption and continuing after an unresolvable target.
- A CLI → tracer → JSON/text integration test uses constructed replies for two TTLs and checks saved output without sending packets.
- Export tests verify per-protocol means across repetitions, zero RTT, missing protocols, empty hops, timeout/error counts and JSON round-tripping.
- Frontend tests cover repeated responses, same-TTL alternatives, hop gaps, protocol/target filtering, hostname toggles, zero RTT, escaping and invalid result roots.
- Original archived documentation, example targets and unchanged CSS were checked against the supplied ZIP.
- Python/JavaScript syntax and local documentation links were checked.

Run the suites from the repository root:

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/frontend.test.mjs
```

## Remaining verification limits

No live probes were sent. Native socket privileges, operating-system behavior, real routing responses and full browser rendering still need verification on a suitable host. The archive does not include a real output dataset; the explorer needs results generated by the CLI.

Traceroute observations do not establish a physical topology. Candidate links spanning unanswered hops or alternative replies are marked as uncertain. Displayed RTT is the round-trip time of a probe to a responding address, not isolated latency of the drawn edge. Sample counts do not measure traffic volume.

Timeout percentages count missing probe responses across protocols. They do not directly measure end-to-end traffic loss, because response behavior varies by router and protocol.

The frontend loads vis-network from an external, unpinned CDN URL. Scapy is pinned, but no full cross-platform environment lockfile or live performance benchmark is supplied. No throughput, accuracy, speedup or real-network success rate is claimed.
